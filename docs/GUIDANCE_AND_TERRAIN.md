# 情境引导与三维雪场

## 第一版范围

- 回答成功收尾后追加 `guidance`：最多三个相关追问、明确雪场的场景入口、相关教学资源。
- 上下文复用 Agent 状态、人类消息历史与画像，不从 AI 回答反向猜雪场、不另建全局会话。比较多个已收录雪场时提供各自入口；简单否定目标不从历史重新带回。
- 当前中文条件识别使用规则，不是完整语义解析。复杂否定、地点描述、指代可能无法识别，用户可补充明确条件。
- HTTP `data.guidance` 与 SSE `{type: "guidance", guidance: ...}` 同构；旧客户端可忽略新字段。前端仅在正常结束后展示，引用重写、失败、停止清空旧引导。

## 教学资源边界

`ski-backend/data/learning_resources.json` 是独立资源目录，**第一版目录为空**。已接通卡片协议与空态，不代表已有可推荐视频。只有教学相关问题或已知单双板的新手情境才显示资源说明。

新增资源时必须人工核验：标题、HTTPS URL、发布者/来源、单双板（单板/双板/通用）、适用水平、主题和资料日期 `updated_at`。日期填资源资料日期，不把抓取日期冒充发布日期。失效或未核验链接不得进入目录；视频链接仅用于打开发布方页面，不下载或转存作品。推荐不代替现场教练，不暗示观看后即可独自上雪道。

## 三维视觉边界

**雪道是主体**：场景以档案里 32 条具名雪道为主角。每条雪道是一条人工设计、尚待与参考图核验的
示意路线（`utils/wanlong.js` 的 `runs`，由 `top/bottom/bow` 生成折线），渲染成压雪宽雪面，
两侧带难度色包边（绿/蓝/红，与页面图例同色），中段有可点击的名称标签。宽度按难度分档
（初级最宽、高级最窄），**只表示难度差异，不是实测米数**。

山体不再是几个圆包：高度场按"南北向主坡面 + 东西向差异（西翼更缓、东端略低）+ 山脊线 +
雪道分组浅沟 + 褶皱"成形，四缘自然落回地面；山脚平台与山顶平台是平的。默认视角从北侧正对
山面，像官方全景图那样一眼看到整片雪道扇形。

树林用抖动网格布点，**雪道走廊、山脚建筑带、山顶平台一律留空**，野雪区（图上 A–U 字母块）
按各自疏密降档；这条"雪道上长不出树"是场景像滑雪场而不是像雪山贴图的关键。

参考图的阅读结论与推测边界见 [TERRAIN_REFERENCE_REVIEW.md](TERRAIN_REFERENCE_REVIEW.md)；
其中明确：山体高度场、雪道视觉宽度、坡面与吊厢动画都是展示设计，**不是实测高程、宽度、
坡度、通行关系或实时设施运行状态**。万龙使用人工设计的近似布局；其他雪场用通用示意，
不得冒充专属复刻。业务长度/坡度等仍从档案及证据弹层读取，不从场景几何推算。

Three.js / OrbitControls 固定为 r128，本地 `static/vendor/` 优先，失败时尝试 CDN；都失败则
页面保留二维示意和实体列表。小屏/低核默认低配；减弱动画跟随系统偏好。页面隐藏暂停，
销毁释放实例缓冲、几何、材质、贴图、监听与 DOM。

## 聊天主流程优化

三维精修暂停，聊天欢迎页改为「第一次滑雪／帮我选雪场／安排一天」三个任务入口。完成的回答按原文段落显示并突出首段，不重写答案或删除引用、安全提醒；流式期间保持原有增量显示。来源入口位于回答后、下一步建议之前；雪场示意缩成可选按钮，空教学目录只显示诚实提示。

失败或停止后保留内容并提供重新询问原问题的按钮（会产生一次新请求，不保证服务端撤回上一轮记忆）。网络与兜底双失败也发出一次 done，释放等待状态。结束回答时不强制把正在翻历史的用户拉回底部。

验证：聊天呈现 3 项测试、SSE 23 项断言、引导 13 项断言通过；使用 HBuilderX 内置 Vue compiler-sfc 编译聊天脚本和模板通过。未运行完整 uni-app H5 构建、真实模型对话或手机外观验收；首段突出并不保证模型一定结论优先，后续仍需真实对话评估。

### 对话表达规则（后续优化）

系统提示词明确首段先答所问、资料不足先说明缺口、追问只选当前最关键条件；复用历史用户消息与行程状态，最新明确更正优先，已知新手不再问水平。简单事实查询不以画像采集阻断；价格日期、样例和安全警示必须就近说明。保持末尾来源编号硬约束及中间件校验，不截短或改写模型正文。

后端 pytest：166 项通过（1 项 Chroma 弃用警告）。检索评估报告数值与 HEAD 基线一致：hit@1 37/42（88%）、hit@3/5 100%、MRR 0.933、拒答 10/10、分层 3/3。评估工具产生完整报告，但 PowerShell 调用返回非零，未取得明确错误原因；不宣称命令完全成功。检索评估不覆盖真实模型对话风格，静态提示词测试亦不能证明模型实际遵守，尚需多轮端到端验证。

### 三轮真实模型复测

使用真实 AgentService.achat、匿名用户和临时 InMemorySaver，未写用户画像或生产 checkpoint。测试首次入门咨询、北京出发想滑双板、上海出发且暂停行程的更正。修复前第三轮仍追问日期；修改行程提示与 set_trip_info 返回后，第三轮正确确认上海/双板/暂未安排，不再追问日期。下一步建议修复了「想滑双板」漏识别。

仍未通过：前两轮仍优先追问日期或天数，首次入门体验尚不足；三轮只是一组实测，不代表模型稳定服从。运行输出含 Pydantic 序列化警告，PowerShell 返回非零，但三轮均得到模型回复。后端回归 169 项通过（1 项 Chroma 弃用警告）。本轮未重新跑完整检索或端到端题集，不能声明指标变化；上一轮检索基线保持作为历史结果。

### 明确入门任务的动态提示

新增 ConversationFocusMiddleware，在模型调用时追加明确任务提醒，不写回消息历史。仅明确入门/暂停表述启用，显式行程、事实或雪场查询退出；来源校验保持原样。真实模型匿名内存会话复测：首轮改问单双板，第二轮确认北京/双板且不问天数，但仍询问雪场偏好，尚未完全遵循只澄清课程/装备的预期。不能宣称整个新手路径稳定通过。过程中一轮模型曾扩展较长装备说明，后续收紧为任务澄清，不把该输出当核验教学资料。未运行完整端到端或最新检索评估，历史指标不能证明本次对话效果。

### 已知地点的重复追问修复

新增 known_location，从历史用户消息提取地点供动态模型提示和 guidance 共用，不从 AI 消息推断；覆盖北京后续承接、上海更正、否定/假设和未定地点。未新增长期画像写入，也未更改检索与引用校验。后端 175 项通过（1 项依赖弃用警告）。

真实模型同线程三轮复测中，第二轮未再次询问出发地，建议沿用北京；第三轮建议改为上海。仅单组实测，不能保证所有场景稳定服从，也不覆盖历史被裁剪后的持久记忆。未重跑检索评估，不能声明检索指标变化。复测仍出现无来源教学扩展和暂停后罗列行程字段，未解决。

测试隔离风险：使用匿名 uid=None 与 InMemorySaver，但 update_profile 的 uid 默认回退到 1，日志显示第二轮向 user_profile 用户 1 提交了更新，因此不能宣称未修改真实画像；原值未知，未盲目回滚。后续真实模型测试应先隔离画像工具或使用专用测试用户。
