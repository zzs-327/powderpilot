# PowderPilot 滑雪情报官 —— Demo 脚本

> 目标：**5 分钟内让面试官/同学相信"这个 Agent 的答案可信"**。
> 核心叙事：不是"我做了个滑雪问答机器人"，而是"我做了个**会拒答、会标来源、会分层的滑雪决策 Agent**"。

## 2. 场景一：结构化统计（演示 SQL 工具，不是 RAG）

**你输入**：`万龙有几条高级道`

**期望表现**（看 `--debug` 或后台日志）：
- **先等十几秒**：气泡上方出现灰底进度条「正在理解你的问题… → 正在查雪道明细…」
  （2026-09-13 新增的流式进度：每个工具一被调用就报一句，等待从"卡死了"变成"看得见的工序"）
- 调用 `get_resort_runs`
- 然后**文字一个字一个字往外蹦**（流式输出，不再是一整段突然出现）
- 回答形如：**转引资料显示 32 条（初级 4 / 中级 9 / 高级 19）；高级 19 条**
- 回答下面出现一排来源标签（`E201` 等），**点开能看到出处 / 信息日期 / 几手数据**
- 生成期间发送键是「停止」，点它会真的停下（气泡下方显示"已停止生成"）

**要讲的一句**：
> "这类数量统计我**不用 RAG**——向量检索做 count 会让模型猜数字。所以走 MySQL 结构化查询。
> 每条雪道的坡度、海拔，证据里都带着'二手转引'的标记。
> 而且连**工具返回给模型的那句话**都按可信度分档生成：数据是二手转引，它就返回
> '转引资料显示共 32 条'，不会写成'官方公布'——工具输出是模型唯一的事实来源，
> 在这一层替数据抬高身份，上游做的可信度分级就白做了。"

> 💡 **顺手可加的一句**（被问"为什么是流式"时）："一轮要十几秒才出第一个字，
> 这十几秒它在检索、查库、算路线。H5 端用 fetch 读流，把这些工序逐条报到界面上。
> 另外引用校验是**后置**的——如果答案被打回重写，后端会发一条 reset 让前端清空气泡重来，
> 否则用户会看到'被判不合格的版本'和'重写后的版本'叠在一起。"

## 3. 场景二：价格 + 保鲜期 + 数据可信度（**这一段最能体现"反照骗"**）

**你输入**：`万龙雪票多少钱`

**期望表现**：
- 调用 `get_resort_price`
- 回答带**录入日期**：`平日全天 560 元/人/天（录入日期 2026-04-06）`
- 主动提示两件事：**"不是官网直采"** + **"距今较久，价格可能已调整"**

**要讲的一句**：
> "价格是时效信息，我给每条价格打了保鲜期，过期会主动提醒。
> 更重要的是——这批价格的来源分级是 `transcribed`（二手转引），不是官网直采。
> 原因是**万龙的官网域名已经失效并被抢注成垃圾站了**，我拿不到官方直采。
> 我没有为了让数据'看起来权威'就把它标成官方，而是在回答里明说'这是转引、建议以官方渠道为准'。
> 连'我们自己的数据是几手的'都告诉用户，这才是反照骗。"

> 如果被问"那你的数据还可信吗？"——答：可信度不是二值的。
> 我把来源分成 `verified 官方直采 / transcribed 二手转引 / sample 示例`，
> `corroborated 多源印证` **在计划中、尚未落地**（别当场说已有）。
> 分级的目的是**告诉用户这是几手数据**，让他自己判断要不要信，不是给数据设门槛。

## 3.4 加演：多雪场对比 +「这数据是几手的」（**2026-09-13 新增，5 雪场后最值钱的一段**）

> 为什么加这段：雪场从 2 座扩到 5 座后，"同一天该去哪家""你说的是哪家的数据"成了最真实的问题；
> 而同一批材料里**既有官网直采、又有来源互相打架**，正好一次把"可信度分级"讲透。

**输入 A**：`北大湖有什么雪道`

- 期望：按**官网原始分类**给出（中级道 16 / 高级道 5 / 中高级道 5 / 初中级道 4 / 初级道 3 / 连接道 1），
  单条带长度/落差/坡度；并说明"官网首页还写着 74 条，与参数表的 34 条不一致，本库不替它取舍"

**要讲的一句**：
> "北大湖是我唯一做到**官网直采**的雪场——它的雪道页是结构化表，34 条参数我逐行抄下来的。
> 但即便官网直采，它**自己的两个页面也对不上**：首页说 74 条，参数表只有 34 条。
> 我没替它选一个，而是两个都留着、都告诉用户。"

**输入 B**：`将军山有多少条雪道` ／ **输入 C**：`松花湖有几条雪道`

- 期望：将军山给出两个口径（61 条 / 分难度合计 48 条，且**明说对不上**、无逐条明细）；
  松花湖给出 50 条（2024-2025 口径）+ 明说"未公布各难度条数，'高级道几条'暂时答不了"

**要讲的一句**：
> "这两家我**没拿到**官方逐条数据，所以我不会为了好看硬提档——它们至今标的是'二手转引'。
> 宁可告诉用户'我只知道总数、明细没有'，也不拿别的雪场的名单凑数。"

**输入 D**（隔离验证，适合当场让评委随便点一家）：`北大湖的高级道有哪些`

- 期望：只出现北大湖的雪道，**不会混进万龙的**——多雪场之后最容易出的错就是拿 A 的数据答 B

**如果被问"你怎么证明没串场"**：
> "评估集里有专门的**跨雪场隔离题**：命中判定要求命中的 chunk 必须带对雪场名，串场就必然不通过。
> 现在 29 道检索题 + 6 道拒答题，hit@5 100%、拒答 100%。"

## 3.5 场景三：外部实时数据（百度地图 MCP，**2026-09 新增**）

**你输入**：`崇礼明天冷不冷？`

**期望表现**：
- 调用 `get_weather`（内部走百度地图 MCP：行政区划解析 → 天气接口）
- 回答里带**实况 + 逐日预报 + 气象预警**，并标注数据更新时间

**再输入**：`从郑州开车去万龙要多久，过路费多少？`

**期望表现**：
- 调用 `get_route`，给出**868 公里 / 约 9 小时 50 分 / 过路费约 364 元**

**要讲的两句**：
> "天气和路线都是外部实时数据，我通过百度地图 MCP 接入。但我**没有把 14 个 MCP 工具直接丢给模型**：
> 一是它们返回的纯 JSON 没有证据编号，会被我自己的引用校验误杀；
> 二是像天气接口要 6 位行政区划码，模型根本不知道崇礼区是 130709。
> 所以我在中间加了一层适配：**参数适配（人类说法→接口参数）+ 输出适配（JSON→可读文本）+ 证据适配（包成标准证据信封）**。"

> "另外滑雪场景里最该拿到的其实是**气象预警**——霜冻、大风直接影响缆车是否停运。
> 这个预警是崇礼区气象台发布的原始信息，我们的证据里连发布机构都带着。"

## 8. 收尾技术串讲（1 分钟）

按这个顺序说，每条一句：

1. **RAG 管线**：YAML 档案 → 中文分块 → Ollama 本地嵌入 → Chroma → **向量 + BM25 → RRF 融合**
2. **为什么混合检索**：雪道名是专有名词，向量召偏，BM25 精确命中，RRF 只按排名融合（避开分数量纲）
3. **防幻觉三闸**：向量距离阈值 0.85（实测标定）→ BM25 关键词覆盖闸门 → 收录范围守卫
4. **引用校验中间件（2026-09 新做）**：证据编号按工具分段保证全轮唯一 → 引用编号白名单 →
   **带单位数字的事实级校验**；不过先打回重写、再不过降级为"暂无可靠来源"
5. **Agent**：create_agent + 9 个工具（6 本地 + 3 外部 MCP）+ 自定义状态机 + 异步 checkpointer + 结构化输出
6. **数据**：YAML 单一真相源 → 一条命令同步 MySQL；改数据只改一处
7. **数据可信度分级**：verified 官方直采 / corroborated 多源印证 / transcribed 二手转引 / sample 示例
8. **指标**：hit@1 83%、hit@3 97%、hit@5 100%、MRR 0.901、拒答 100%、分层 100%（35 检索 + 6 拒答，8 座雪场）
   —— 强调一句："基线是 2026-09-13 重标定过的，雪场从 2 座加到 5 座、题目从 18 道扩到 29 道，新增的是跨雪场隔离这类更难的题，所以别拿旧数字比绝对值。"

## 8.5 如果被追问"你的引用校验到底拦得住什么"（**高价值追问**）

这一段建议主动讲，因为它是"反照骗"最硬的技术落点：

> "只校验'引用的编号存不存在'是不够的——模型编一个'雪票 380 元'，
> 照样能给它标上一个合法的 [E301]，编号校验完全放行。
> 所以我又加了一层**事实级校验**：回答里带单位的数字，必须能在本轮证据里站得住。
>
> 这一层前后改了四版，每一版都是被真实误报/漏报逼出来的：
> - 第一版只比数值大小 → 证据里'银龙道最大坡度 **15 度**'给编造的'高级道 **15 条**'背了书
> - 第二版允许任意两数相加 → 16 度 + 19 条 = **35**，编造的'35 条雪道'被放行
> - 第三版定成 **(数值, 单位) 配对 + 同单位内才允许推算** —— 这一条同时解决了
>   跨单位凑数（漏报）和温差算不出来（误报）
> - 第四版补**跨轮回看窗口**：白名单原来只认本轮证据，可是模型的引用是跨轮连续的——
>   追问'那价格呢'时它会把上一轮的编号一起带进回答，于是被判'引用了不存在的编号'，
>   重写还带着它，最后**降级成拒答**。最普通的追问路径被判死，而且每打回一次就白等一轮。
>   现在改成：本轮**有**证据时，允许沿用最近 3 轮出现过的编号与数字；
>   但本轮空手而归（工具回了'未收录'）或压根没调工具时，这个窗口一律不生效——
>   否则'未收录的雪场'会被答成上一个雪场的价格，那是最坏的一种错。
>
> 还有两个坑也值得说：金额推算必须**认中文数字**，因为用户说的是'三个人'，
> 不认它，模型算对的'三人合计 1680 元'会被判成编造；
> 而 POI 的'人均 166.8 元'被模型四舍五入成 167 元，也算误报——
> 最后是按回答自身的小数位数去 round 证据值，既放过 167、又拦得住 168。"

> **一句话总结**："校验的难点不是写出规则，而是**把误报压下去**——
> 误报的代价是用户直接看到'暂无可靠来源'，比漏掉一条更难受。
> 我为此写了两层东西：一个离线验证脚本（**49 项断言**，不需要 API key，把每条边界固化成测试），
> 外加一个压测脚本（6 个场景 × N 轮，直接给出**降级率 / 打回次数 / 平均耗时**）——
> 改完规则跑一遍就知道是变好还是变坏，不靠感觉。"

## 9. 异常兜底（提前想好，别当场慌）

| 现象 | 当场怎么说/怎么做 |
|---|---|
| 模型接口 401/超时 | "接口额度问题"，立刻转演示**评估报告 + 中间件离线验证**（都不依赖模型） |
| 天气/路线查不到 | 说明"这是外部 MCP 服务，可能限流"，转演示本地三问（雪道/价格/避坑） |
| 回答没有调工具 | 补一句"请查一下知识库"，或直接展示 `--debug` 的工具调用日志 |
| 行程卡没生成 | 检查是否 5 个要素齐了（缺就补说一句"两个人"） |
| 实拍图显示占位块 | 说明"图片本体在 MinIO，演示环境只放了元数据；拍摄日期与拍摄者仍可溯源" |
| 前端登录失败 | 用命令行 `python -m scripts.chat_cli --debug` 演示，效果一样 |
| 出现"抱歉，这条回答没能通过来源校验" | 先看 `logs/backend.log` 里的 `引用校验未通过` 那一行（**原因、本轮调了哪些工具、被判不合格的原文都在里面**），再决定怎么解释：真编造 → "说明校验在工作"；误伤 → "这正是我在压的东西，误伤率有压测脚本量化"。**不要只会说"这是特性"** |

## 10. 录屏建议（如果要做视频）

必拍的 4 个画面：
1. `--debug` 输出里的**工具调用链**（证明 Agent 在自主决策，不是模板）
